本文件只改谁能打开复盘页，以及打开后看到哪一视角。轻量卡发给谁、正文里放不放「销售表现」，仍按前置说明书。历史说明书不改。

## 1. 谁能打开

`GET /crm/visit_records/{record_id}/recap` 在下面两类人时返回 200：

- 跟进记录数据范围里能看到这条拜访的人。
- 这条拜访的个人收件人：记录人、直接汇报上级、抄送、协同人。看不到拜访详情也可以打开。

记录不存在，或者既看不到拜访、也不是个人收件人，返回 404，文案都是「跟进记录不存在或无权限访问」。

部门群的卡片发到群，没有个人名单。群里的人点「完整复盘报告」时，仍要能看到这条拜访，或者已经是上面的个人收件人。能看页面的人不因此收到卡片。

同一个人的收件角色优先级不变：记录人高于直接汇报上级，高于抄送，高于协同人。

## 2. 打开后看到什么

能打开但当前身份没有可看的报告时，HTTP 仍是 200。`view`、`insight`、`performance` 为空，`tabs` 为空。

有可看的报告时，`tabs` 仍是「业务推进」和「销售表现」。缺的那份为 `null`。另一视角的内容不返回。结构化抽取仍只给记录人。

| 打开的人 | 页面 |
| --- | --- |
| 记录人 | 销售视角的业务推进和人员表现评价，并带抽取 |
| 纯协同人 | 销售视角的业务推进和人员表现评价，抽取为空。看不到这条拜访、又没有销售视角报告时，页面为空，不返回上级视角 |
| 纯协同人，能看到这条拜访，但没有销售视角报告 | 上级视角的业务推进。人员表现评价为空 |
| 抄送 | 上级视角的业务推进。人员表现评价为空 |
| 直接汇报上级 | 上级视角的业务推进和人员表现评价。抽取为空 |
| 其他能看到这条拜访的人 | 上级视角的业务推进。人员表现评价为空 |
| `biz_admin`、`sys_admin`、`executive`，并且能看到这条拜访 | 上级视角的业务推进和人员表现评价。抽取为空。记录人本人仍走销售视角 |

直接汇报上级只算这条记录人的汇报链上一级。`biz_admin`、`sys_admin`、`executive` 如果看不到这条拜访，只是因为抄送或协同人才进来，页面仍会给出上级视角的人员表现评价。他们的卡片里没有这段。

只有上级视角的人员表现评价、没有业务推进时，直接汇报上级和上述三类管理员能打开。其他人得到空页面，列表上的 `has_recap` 为 false。

## 3. 列表

`has_recap` 只标在当前用户已经能看到的拜访上。只靠卡片进来的人不在列表里。

记录人或纯协同人：销售视角的业务推进或人员表现评价至少有一条未删除、未过期时为 true。抄送同时是协同人时，不按协同人计算。

其他人：上级视角的业务推进存在时为 true。只有上级视角的人员表现评价时，仅直接汇报上级或上述三类管理员为 true。

导出不计算这个字段。

## 4. 验收

- 看不到拜访的纯协同人能打开页面，看到销售视角，没有抽取；只有上级视角报告时页面为空。
- 看不到拜访的抄送能打开页面，只看到上级视角的业务推进。
- 能看到拜访、但不是收件人的人能打开页面，只看到上级视角的业务推进。
- 直接汇报上级和能看到这条拜访的三类管理员看到上级视角的两份报告。
- 部门群里的人，如果看不到拜访，也不是个人收件人，打开链接得到 404。
- 轻量卡的收件人和正文不因这次改变。
