本文件新增一张发给 CXO 的例会管理评价卡，以及这条评价的抽取查询。负责人和提交人的例会复盘卡不改。历史说明书不改。

## 1. 卡片

Aldebaran 写好管理评价后，调用 `POST /api/v1/notification/push`，`type=leader_meeting_review_cxo_card`。

卡片标题是「例会管理评价｜负责人｜日期」。查到原例会负责人姓名时，正文第一行写「负责人：姓名」，下面才是这条洞察的摘要。查不到姓名时，标题仍是「例会管理评价｜日期」，正文只有摘要。有完整评价、并且带了原复盘报告 id 时，摘要下面放「完整评价报告」，打开这场会报告页的「管理评价」。地址只带这场会的报告 id，不带日期。有了这场例会复盘报告，才有对这个例会负责人的管理评价报告。同时再加「原复盘报告」，打开同一页的「经营复盘」。抽取项用底部按钮跳转，多于一条时带条数。只有「管理方法建议」。卡片上不展开单条建议。总评、关键数据、已解决、未解决留在管理评价全文里，不抽成条目。

一场会仍是报告页上的一行。页内两个 tab，默认「经营复盘」，再加「管理评价」。没有管理评价时不出现第二个 tab。每个 tab 是一份报告，各自有查看抽取的入口。两份报告正文都不由本服务返回，都由 base-api 提供。base-api 按这场会的报告 id 取未删除、未过期的最新一条管理评价，响应带洞察 id。

## 2. 发给谁

默认不发。打开推送开关后，收件人与 CXO 今日重点相同：策略里写了名单就用这份本地 user id；没写时用公司日报接收人。请求可以带本地 user id，只能从这批人里收窄，不能另加。不带则整批都发。不进群，不计费，不抄送，也不套用今日重点的退订。

开关关闭时，推送接口仍成功，但不查收件人、不读评价、不发卡片。抽取查询不受开关影响。

某人没有 open_id 或发送失败时，其余人仍收卡。有一人发出则这次算发出。没有可发的人、洞察对不上或没有内容时不发，接口仍是 HTTP 200。重复调用会再发。

## 3. 读哪一份

请求给出一条或多条洞察 id。只读人员身上、类型为管理评价、未删除且未过期的行。多于一条时用最新的一条。摘要、完整报告和抽取都没有时不发。只有完整报告或抽取、没有摘要时，正文写「--」，链接或按钮仍在。

## 4. 抽取

只有会收到 CXO 今日重点的人能查看这条洞察上的抽取。被评价的原例会负责人若不在这份名单里，不能看。他若自己也是 CXO，可以看对自己的评价，也能改。其他人打开是无权限。返回分类后的条目和入口，不返回管理评价全文。没有抽取时是空的。这些条目不出现在负责人那张卡和原来的抽取页。

能看的人就能改。管理方法建议可以赞踩、采纳、拒绝、挂任务和评论，用的就是例会复盘那几个写入接口。评论不会默认发给被评价负责人。

## 5. 验收

- 默认不发评价卡。打开开关后，收到卡的人就是会收到 CXO 今日重点的人。
- 请求里多写一个名单外的人，这个人收不到卡。
- 正文是摘要。带了原复盘报告 id 且有完整评价时才出现「完整评价报告」，打开「管理评价」。飞书按钮按上面的顺序。钉钉把抽取入口写成正文下方同一行蓝链。企微与飞书同一套文案：有全文时主跳转是「完整评价报告」，并另有「原复盘报告」，横栏是「管理方法建议」。没有全文时主跳转改为「管理方法建议」。
- 抽取页能看到管理方法建议，一条是建议本身和原因。响应里没有管理评价全文。只有 CXO 今日重点的接收人能看、能赞踩、采纳、拒绝、挂任务和评论。被评价的人自己也是 CXO 时，可以打开对自己的评价。
- 负责人和提交人的例会复盘卡仍是会议总结、待办候选和经营事项。
