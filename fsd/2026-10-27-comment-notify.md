本文件描述写评论时怎么指定提醒接收人，以及今日需介入评论卡长什么样。历史说明书不改。评论盖楼、编辑规则、拜访 / 周跟进链接打开方式见前置说明书。

## 1. 这次做什么

拜访记录、周跟进、今日需介入写评论都可以带 `recipient_user_ids`。有非空名单就只提醒这些人；不传或空列表走默认。名单是本地 user id，不落库。页面上要保留点名时，前端把 `@姓名` 写进 `content`。

回复时前端把被回复评论的 `author_id` 放进名单，点名人一并放入，走同一条指定人链路。不传名单时服务端仍按默认发给被回复作者。

名单里的自己会跳过。无效 id 发不出去，不影响评论已经保存。`type=task` 仍不推。销售今日重点没有评论。

## 2. 默认接收人

| 场景 | 不指定时 |
| --- | --- |
| 拜访顶层 | 记录人 |
| 周跟进顶层 | 负责人 |
| 今日需介入顶层 | 不推。负责人记在自己卡片上，点名了才通知销售 |
| 任意回复 | 被回复作者 |

## 3. 今日需介入卡片

负责人在自己的需介入上写评论，推给被提及的销售。销售看不到负责人今日重点页，这条评论也不在销售自己的今日重点上，所以卡片只给一句话，没有跳转。

顶层标题是「{作者}给你留了评论」，回复是「{作者}回复了你的评论」。客户名加商机名（没有则用事项）作为正文上下文，不是链接。拜访 / 周跟进仍按 `fsd/2026-10-27-comment-im-applink.md` 带侧栏按钮。

## 4. 验收

- 不传或传空列表：拜访 / 周跟进顶层仍给记录人 / 负责人；今日需介入顶层不推；回复仍给被回复作者；自己给自己不推。
- 传了非空名单：只发给名单里的人。
- 名单里有自己时跳过自己，其他人照发。
- 今日需介入飞书 / Lark 卡片有标题和引用，没有按钮，也不出现 `/v2/department-highlights` 或 `/v2/today-highlights`。
