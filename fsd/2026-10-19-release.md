## 1. 这次发版做什么

两部分：收紧拜访复盘的可见范围，以及新增今日重点的查询和推送。

## 2. 拜访复盘

相对历史版本：

- `item_type=CONCLUSION` 的抽取不回传 `status`。其他类型仍回传。库内的 status 不改。
- 能打开复盘的人收窄为记录人和该记录人的汇报链上级。其余人，包括其他协同人，没有可看的复盘。
- 记录人看销售视角，并看到结构化抽取。汇报链上级看上级视角，不附带抽取。
- 列表用 `has_recap` 表示当前用户打开复盘页时，对应视角是否已有复盘。导出不计算这个字段。
- 没有复盘行时，不查汇报链，也不读抽取表。
- 记录人看到的结构化抽取里，「当前最关键问题」只含 `KEY_GAP`。若某条建议动作的 `related_gap` 指向这个缺口，该缺口同时从按钮和 `items.KEY_GAP` 中去掉，两边的条数一致。全部被覆盖时，这个入口不出现。`RISK` 不再进入这个入口。行上若已有 `card_links` 快照，入口以快照为准；隐藏规则只在解析出的入口配置带 `hide_when_covered_by_action` 时生效。

10 月 14 日之后又做了这些修正，不改变上面的收窄：

- 系统管理员阅读拜访复盘时看上级视角，不附带结构化抽取。角色查询失败时不放开。记录人仍看销售视角；记录人同时是管理员时仍按记录人处理。
- 上级视角的存储类型改为 `POSTVISIT_REVIEW_LEAD_VIEW`。列表 `has_recap` 使用同一规则。
- 实体洞察模型补上已有列 `period_key`。日报告的取值是 `YYYY-MM-DD`，周是类似 `FY26W42`。字段说明把它和实体类型、实体 id、洞察类型一起称为更新键。这次没有新增迁移，本仓库也没有按这个键做读写或 upsert。

## 3. 今日重点

本次增加两类今日重点接口。都只认当前登录人，请求里不能指定别人。

| 内容 | 接口 |
| --- | --- |
| 当前用户自己的销售抽取 | `GET /api/v1/crm/today-highlights/sales` |
| 当前用户自己的今日需介入 | `GET /api/v1/crm/today-highlights/departments` |

抽取正文由 Aldebaran 写入。本服务负责查询、赞踩、采纳或拒绝、评论、挂任务，以及按策略发卡。

成功响应为 `{ "code": 0, "message": "success", "data": {} }`。参数和权限错误返回 HTTP 错误，body 为 `{ "detail": "..." }`。

### 3.1 一线销售

#### 3.1.1 看到什么

`GET /crm/today-highlights/sales?report_date=YYYY-MM-DD`。不传日期则取北京时间当天。日期格式错误返回 422。

当前用户没有 oauth 身份，或当天没有可展示条目时，HTTP 200，`items` 为空对象。

区块按返回的 `card_links` 渲染，标题用 `title`，并带 `count`。没有条目且快照里也没有的区块不出现。

| key | 抽取类型 | 何时出现 |
| --- | --- | --- |
| `immediate_today` | `IMMEDIATE_ACTION` | 当天有立即处理 |
| `open_risks` | `OPEN_RISK` | 风险有变化。`gap_only`、`not_formal_risk`、`risk_change=unchanged` 不展示 |
| `next_week_confirm` | `NEXT_WEEK_ACTION_CANDIDATE` | 只在周五 |

已删除和 `SUPERSEDED` 的行不展示。同一类型、同一抽取键当天被重新抽取后仍只显示一条。最新一行自己已经采纳或拒绝时，整行用最新行。否则正文用新说法；若有一行已采纳或拒绝且不会被作废，`unique_id`、采纳状态和赞踩留在那一行。

每条给出主张、原因、置信度、依据、客户和商机名称。立即处理另有「为什么是今天」「做完的标准」「拖下去的影响」。风险在 `risk_change=resolved` 时表示已闭环，并排在该区块最后，其余按置信度从高到低。下周待确认优先展示 `confirm_prompt`。

状态字段：`PENDING` 待判断，`ADOPTED` 已采纳，`REJECTED` 已拒绝。另有拒绝原因、可选的已有任务编号、赞踩和赞踩时间。

#### 3.1.2 能做什么

销售对三个区块使用同一套写入，不能调用负责人的评论和挂任务接口。

- 采纳或拒绝：`POST /crm/today-highlights/sales/items/decisions`。点采纳立即提交。点拒绝可填写原因，允许为空。已采纳可以再拒绝，已拒绝可以再采纳，后一次覆盖前一次。没有回到待判断的操作。不是自己的条目 `ok` 为 false。带了任务编号时，该任务必须存在且未删除，否则整批返回 422，不改采纳状态。
- 赞踩：`POST /crm/today-highlights/sales/items/{unique_id}/feedback`。`up` 或 `down`，再点当前选项即撤销，点另一个即切换。点赞和点踩都可以带最多 500 字附言。空 `feedback` 表示撤销，并清空附言。
- 条目不存在或不属于当前用户时返回 404。

销售页不建任务。采纳时可以带一个已经存在的任务编号。

#### 3.1.3 卡片

定时或手动推送时，只给本人发一张卡，标题为「今日重点｜日期」。

- 正文只展开一条立即处理：已闭环的排在最后，其余按置信度从高到低，取第一条。还有其他条时，入口写「更多（N）」，链到 `tab=immediate_today`。
- 商机风险、下周待确认是蓝链，多条时带条数。
- 每天可打开「本周待完成」：本人、预计完成日在本周一到本周日、状态为 `IN_PROGRESS` 或 `PENDING`。
- 周二到周日可打开「本周已拜访」。周一没有这一项。
- 解析不到本人姓名时，卡片不放这两个按钮。

变体关闭、当天没有内容、没有平台身份、本人关掉该变体时，不发空卡。

另提供 `GET /crm/sales/week-visits`，统计当前用户本周拜访总数，以及每条拜访最新一条销售视角复盘的严重度数量。`week_start` 优先于 `report_date`，都缺省则取北京时间当天所在周。

### 3.2 销售负责人

#### 3.2.1 看到什么

`GET /crm/today-highlights/departments?report_date=YYYY-MM-DD`。只返回 `subject_type=USER`、`audience=leader`、`item_type=TODAY_INTERVENTION`，且 `subject_id` 等于当前用户 oauth id 的行。不接受部门 id，也不读取一线销售抽取。

没有 oauth 身份或没有可展示条目时，HTTP 200，`departments` 为空数组。

每条需介入包含主张、原因、依据、客户、商机、相关销售、管理问题、今日窗口、建议动作、事后核验和介入类型，以及赞踩、采纳状态、评论和已挂任务。这个列表接口不返回团队拜访对照。对照只出现在推送卡片上，规则见 3.2.3。

#### 3.2.2 能做什么

只处理当前负责人自己的需介入条目。无权限返回 404，批量接口里无权限的条目 `ok` 为 false。

- 采纳或拒绝：`POST /crm/today-highlights/departments/items/decisions`。覆盖规则与销售相同。带了任务编号时，任务必须存在且未删除，否则整批返回 422。
- 赞踩：`POST /crm/today-highlights/departments/items/{unique_id}/feedback`。点赞和点踩都可以带最多 500 字附言，撤销时清空。
- 评论：`POST /crm/today-highlights/departments/items/{unique_id}/comments`。正文不能为空，最多 2000 字。`reply_to_id` 必须指向本条已有评论。`author_id` 要么不传，要么等于当前用户。
- 挂任务：`POST /crm/today-highlights/departments/items/{unique_id}/tasks`。任务在其他服务先建好，这里只写回任务 `unique_id`。`adopt=true` 时同时标为已采纳。

#### 3.2.3 卡片

负责人一人一天一张卡，只发个人，不进部门群，不抄送。`department_ids_in_scope` 仍留在代码里，查询、写入和这次推送都不调用它。

- 变体 `department_highlights` / `today_highlights` 关闭时不发。
- 当天有需介入抽取时，收件人是抽取行 `subject_id` 对应的在职用户，不是组织架构上的部门负责人名单。团队接收人和部门群不接收。
- 这条推送做 opt-out 时不带部门 id。因此只命中「关掉全部部门今日重点」的偏好。只关掉某一个部门的偏好不会挡住这张卡。
- 对照用的部门名来自该用户资料上的 `department`，不是他所辖的全部部门。周一对照上一周，周五对照本周，其他日子不附对照。先写团队拜访总数和复盘需关注条数，再点名。负责人本人不计入团队总数，也不被点名。拜访偏少：团队里有人录入时，这一周一条都没录入的成员，全员都是 0 时不点名。需关注偏多：销售视角复盘 `severity=HIGH` 至少 2 条，并且不少于团队人均的两倍。对照查询失败时不挡住需介入卡片。
- 周一、周五如果完全没有需介入抽取，才按有负责人的部门另发只有对照的卡。这条路径会带上部门 id，按部门关掉今日重点可以挡住它。
- 公司今日重点槽位 `company_highlights` 仍只存在于场景目录和推送策略。这次不发公司卡。

## 4. 推送开关

今日重点与日报定时任务分开。

- 总开关 `CRM_TODAY_HIGHLIGHTS_ENABLED`，默认关闭。cron 默认每天 08:00。
- 即使定时任务打开，仍要 `report_push_policy` 里对应变体为开启才发送。销售看 `sales_daily.today_highlights`，负责人看 `department_highlights`。未配置策略时这两个变体都是关闭。
- 超级管理员可用 `POST /crm/today-highlights/trigger-task` 手动触发。`audience` 为 `sales`、`department` 或不传。不传则两边都推。
- `POST /notification/push` 增加 `type=sales_today_highlights` 和 `type=department_today_highlights`，发卡规则与定时任务相同。

偏好接口把销售今日重点放在个人日报的 `today_highlights` 变体下，把部门今日重点放在独立场景 `department_highlights`。只关掉个人日报的 `kpi_card` 不会关掉今日重点，只关掉今日重点变体也不会关掉日报。`sales_daily` 上变体为空的关闭记录会同时关掉日报和今日重点。

## 5. 验收

- 销售只能看到并修改自己的今日重点。负责人只能看到并修改自己的需介入。互相不能写对方的接口。
- 周五才出现下周待确认。未变化的风险不出现。周一的销售卡没有「本周已拜访」。
- 团队拜访对照只出现在推送卡片上。有需介入时收件人是抽取行上的 oauth 用户；没有抽取时，周一和周五才按部门负责人发对照卡。本人不被点名。
- 变体关闭、空内容、无 open_id、用户已关闭时不发空卡。负责人卡不进群。
- 默认定时任务关闭。打开后仍受推送策略控制。
- `CONCLUSION` 抽取不回传 `status`。其他抽取类型仍回传。
- 建议动作已用 `related_gap` 指向的 `KEY_GAP` 不出现在关键问题入口和条目列表中。没有剩余缺口时不返回该入口。
- 只有记录人和其汇报链上级能打开复盘。其他协同人不能。导出不含 `has_recap`。
- 系统管理员能打开上级视角复盘，看不到抽取。非记录人、非上级、非管理员仍然没有复盘。
