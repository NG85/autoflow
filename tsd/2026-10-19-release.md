## 2. 拜访复盘

`visit_record_extract_reader.serialize_extract_item` 在 `item_type=CONCLUSION` 时把返回的 `status` 设为 `null`，不改库内列。

`60056b7e` 起，`recap_view_for_viewer` 只在记录人或汇报链上级时返回视角，其他人返回空。`visit_record.py` 的 `has_recap` 用同一判断；导出路径不填这个字段。之后 `7105d023` 让 `RecapViewContext.view_for` 在非记录人且 `SYS_ADMIN` 时走上级视角。`e2775fad` 把上级洞察常量从 `POSTVISIT_REVIEW_LEADER_VIEW` 改为 `POSTVISIT_REVIEW_LEAD_VIEW`。

`65eaf163` 在 `visit_record_extract_reader.py` 里收紧关键问题。`resolve_card_link_specs` 仍优先用抽取行上的 `card_links` 快照，没有快照才用 `CARD_LINKS_BY_PROFILE`。兜底配置里 `key_issues` 的 `item_types` 改为只有 `KEY_GAP`，并带 `hide_when_covered_by_action`。`related_gap` 从 `SUGGESTED_ACTION` 的 payload 展到条目上。`_omit_covered_key_gaps` 按这些键从 `items.KEY_GAP` 删除对应缺口，删空则去掉这个键。`build_card_links` 对带该标志的入口用同一集合过滤后再计 `count` 和 `preview`；过滤后没有条目则不返回该入口。库内抽取行不改。

## 3. 数据

### 3.1 抽取表

`crm_skill_extract_items` 已由 Aldebaran 创建。Autoflow 只映射，不建表、不迁移。模型：`backend/app/models/crm_skill_extract_items.py`。

查询条件：

- 销售：`report_date` + `subject_type=USER` + `subject_id=当前用户 oauth_user_id` + `audience=sales`
- 负责人：`report_date` + `subject_type=USER` + `subject_id=当前用户 oauth_user_id` + `audience=leader` + `item_type=TODAY_INTERVENTION`

本服务可更新这些列：`status`、`adopted_todo_id`、`reject_reason`、`feedback`、`feedback_comment`、`feedback_user_id`、`feedback_at`。`payload` 和 `card_links` 只读。区块标题从 `card_links` 快照读取，不另建标题表。

过滤在服务内完成：`is_deleted`、`status=SUPERSEDED`，以及销售侧的受众、周五限制和风险变化。客户名、商机名分别查 `crm_accounts`、`crm_opportunities`。名称查询失败时字段为空，不让列表失败。

### 3.2 互动表

新表 `crm_subject_interactions`，迁移 `backend/app/alembic/versions/a8c1e4b7d902_add_crm_subject_interactions.py`。

一行一条。`subject_type=skill_extract_item`，`subject_id` 为抽取 `unique_id`。

- `kind=comment`：评论正文、作者、`reply_to_id`
- `kind=task`：`todo_id` 指向 `crm_todos.unique_id`，任务正文不在这张表

同一业务对象上的同一个 `todo_id` 唯一。评论和任务在列表组装时挂到条目上；拼装失败只记日志，需介入正文仍返回。

赞踩和采纳状态写在抽取表上，不写这张互动表。

### 3.3 洞察模型

`backend/app/models/crm_entity_insight.py` 对齐已存储的数据，本次不新增迁移：

- `entity_type` 补充 `USER`、`DEPARTMENT`
- `entity_id`：拜访为 `record_id`，用户为 `owner_id`，部门为 `department_id`
- 新增可空 `period_key`，与库中已有列对齐。日报告取值 `YYYY-MM-DD`，周为 `FY26W42` 这类键。字段说明把它和 `entity_type`、`entity_id`、`insight_type` 称为 upsert 键。本仓库没有读写这个字段，也没有按它做 upsert

上级复盘读取常量改为 `POSTVISIT_REVIEW_LEAD_VIEW`，定义在 `visit_record_insight_reader.py`。

## 4. 身份

销售列表和销售写入用 `user_profiles.oauth_user_id`。没有该值时列表为空，写入找不到条目。

负责人列表调用 `leader_oauth_id`：用当前登录用户 id 找 profile，再取 `oauth_user_id`，以此作为抽取行的 `subject_id`。`department_ids_in_scope` 仍定义在 `department_today_highlights.py`，没有调用方。

系统管理员判断调用 `oauth_client.check_user_has_role(role="SYS_ADMIN")`。异常时视为不是管理员。`RecapViewContext.view_for` 的顺序是：记录人优先，其次管理员看上级视角，否则才看是不是汇报链上级。

## 5. 推送

`backend/app/celery.py` 在 `CRM_TODAY_HIGHLIGHTS_ENABLED` 为真时注册 beat 任务 `push_crm_today_highlights`，队列 `cron`。cron 来自 `CRM_TODAY_HIGHLIGHTS_CRON`，解析失败时用每天 08:00。配置默认关闭，定义在 `backend/app/core/config.py`。

`push_crm_today_highlights(report_date_str, audience)`：

- `audience=sales` 调用 `handle_sales_today_highlights`
- `audience=department` 调用 `handle_department_today_highlights`
- 不传则两边都执行

销售发送步骤：策略变体开启 → 按主体分组 → 跳过空内容 → 用 oauth id 找在职 profile 和 open_id → 按 `sales_daily` / `today_highlights` 去掉 opted out → `deliver_highlight_card`。飞书和 Lark 走无模板 Markdown 卡；钉钉以及其他带平台标识的收件人走平台 Markdown 卡。卡片正文取立即处理排序后的第一条：`risk_change=resolved` 排在后面，其余按置信度从高到低。

负责人发送按抽取行的 oauth 主体一人一张卡。收件人用 `get_by_oauth_user_id` 找到在职 profile。`deliver_department_highlight_card` 直接向该平台发个人消息，不走会抄送运维的批量发送，也不解析部门群。这条路径调用 `filter_opted_out_recipients` 时 `department_ids` 为空，因此只命中部门 id 为空的关闭记录。

有抽取时，拜访对照的部门名取该 profile 的 `department`，再交给 `load_leader_visit_watch`。列表接口 `highlights_for_leader` 不调用拜访对照。周一和周五完全没有抽取行时，才由 `_visit_only_leader_buckets` 按有负责人的部门准备对照卡，并把部门 id 传入 opt-out。

跳过原因包括 `variant_disabled`、`source_unavailable`、`empty_highlights`、`no_open_id`、`opted_out`、`send_failed`。

团队拜访对照的统计口径与 `sales_week_visits.summarize_week_visit_recaps` 相同：拜访按录入人和 `visit_communication_date` 落在目标周，复盘取每条拜访最新一条 `POSTVISIT_REVIEW_SALES_VIEW`。卡片只使用 `severity=HIGH`。

## 6. 卡片链接

`push_page_urls.py` 生成写进卡片的 URL：

- 销售今日重点：`/v2/today-highlights?date=YYYY-MM-DD&tab={card_link.key}`
- 负责人今日重点：`/v2/department-highlights?date=YYYY-MM-DD`
- 本周待完成：任务列表，状态过滤为 `IN_PROGRESS` 与 `PENDING`
- 本周已拜访：拜访列表，日期为本周一到本周日
